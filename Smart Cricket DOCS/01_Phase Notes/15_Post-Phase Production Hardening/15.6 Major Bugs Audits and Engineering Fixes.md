# 15.6 Major Bugs Audits and Engineering Fixes

## Problem

Several bugs were dangerous because they made the product appear more reliable than it was. The hardening work fixed the highest-risk ones and documented the remaining external gates.

## Important Fixes

### Filename Inference

Symptom: an upload could be treated like a stored dataset sample if the filename matched.

Root cause: dataset lookup and upload analysis were too close together.

Fix: production `/analyze` now validates and analyzes uploaded bytes. Dataset analysis lives behind a disabled development endpoint.

Regression test: invalid bytes with a known dataset filename are rejected.

### Camera Cleanup

Symptom: retake/review state could stop the live stream.

Root cause: stream cleanup and preview URL cleanup were coupled.

Fix: stream lifecycle and object URL lifecycle are separate.

### MP4/WebM Mismatch

Symptom: browser recording could label files incorrectly.

Root cause: MIME support was not negotiated cleanly.

Fix: the frontend selects supported recorder formats and keeps MIME type and filename extension aligned.

### Forged History

Symptom: the browser could create rows that looked like trusted saved analysis.

Root cause: client-side writes were treated as trusted.

Fix: server-owned persistence returns `analysis_session_id`; frontend labels unsaved and demo rows.

### Feedback Without Evidence

Symptom: user feedback could look like training data without reviewable evidence.

Root cause: feedback schema did not fully separate metadata from review candidates.

Fix: training candidates require consent, verified analysis binding, retained evidence, non-expiry, and human review.

### Provider-Aware Deletion

Symptom: deletion could depend on the currently configured evidence provider instead of the original storage provider.

Root cause: provider identity was not treated as retained metadata.

Fix: deletion resolves the provider from stored evidence metadata.

### Timeout Limitation

Symptom: a thread-based timeout can return a 503 while Python computation may continue.

Root cause: `future.cancel()` cannot terminate a running thread.

Current state: queue and caller timeout are bounded, but true process isolation remains a future/external hardening gate.

## Interview Implications

Short answer: the biggest improvements were not cosmetic; they made the system tell the truth.

Deep answer: Production engineering is mostly about preventing false trust. Every fix tightened the boundary between demo behavior, verified backend state, and real ML evidence.
