# 15.9 Supabase Reviewer Access and Private Evidence

## Problem

Retained model-improvement evidence must be inspectable by trusted reviewers, but raw clips must not become public assets.

If the system only stores a clip hash, reviewers cannot verify whether the user feedback is correct. If the system exposes a public URL, it creates a privacy risk.

## Concept

The safe pattern is:

```text
Private Storage Object
→ server-side provider resolves stored provider ID
→ trusted reviewer command requests short-lived access
→ backend uses server credentials to create a signed URL
→ reviewer inspects evidence
→ URL expires
```

The frontend never receives the Supabase service-role key.

## Implementation

`backend/api/evidence.py` implements provider-aware access:

- local development evidence returns a bounded local maintainer path;
- Supabase Storage evidence creates a short-lived signed URL from the private bucket;
- invalid paths and provider failures return explicit error states.

Reviewer access is requested through:

```bash
python scripts/review_feedback_candidates.py list --include-access
```

This command should only run in a trusted backend or maintainer environment.

## Why This Matters

This keeps user data private while preserving the evidence needed for human-in-the-loop review. It also keeps model-improvement feedback honest: a row can be a candidate only when evidence exists, has not expired, and has not been withdrawn or deleted.

## Failure Modes

- Supabase bucket missing: access fails with configuration error.
- Signed URL request fails: reviewer access is unavailable, but the record does not become public.
- Evidence expired: candidate listing excludes the row.
- Consent withdrawn: training eligibility is disabled and evidence deletion is attempted.

## Interview Implications

Short answer: Evidence is private by default, and reviewer access is generated server-side for a short time.

Deep answer: The system separates durable metadata from protected media access. It stores the object path and provider ID, then uses that original provider to delete or issue access later. This avoids both public raw clips and provider-mismatch deletion bugs.
