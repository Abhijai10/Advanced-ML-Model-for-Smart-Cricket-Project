# 15.8 ML Evaluation Governance and Release Evidence

## Problem

The Phase 8 model has useful development metrics, but those metrics are from a small deterministic split. They do not prove unseen-player generalization, calibration, or real-world coaching reliability.

The production-hardening pass therefore adds evaluation tooling without changing the model or claiming better accuracy.

## Concept

A production ML claim needs more than accuracy. Smart Cricket needs:

- player-disjoint splits;
- no player leakage between train, validation, and test;
- class-wise metrics;
- confusion matrix;
- calibrated confidence;
- expected calibration error;
- Brier score;
- confidence/rejection analysis;
- reliability diagrams;
- drift monitoring hooks.

## Implementation

The new evaluation module is:

```text
ml/src/evaluation/
```

Important files:

- `player_disjoint_split.py` creates train/validation/test manifests where a player or group appears in only one split.
- `calibration_report.py` reads prediction files and calculates reliability, ECE, Brier score, class metrics, confusion matrix, and rejection curves.
- `evaluate_predictions.py` is the reproducible entry point that writes a versioned report and reliability SVG.

Example:

```bash
python -m ml.src.evaluation.evaluate_predictions \
  --predictions ml/artifacts/evaluation/player_holdout_predictions.csv \
  --output-dir ml/artifacts/evaluation \
  --labels cover_drive,defensive_shot,pull_shot,sweep_shot
```

## Why This Matters

Confidence is not automatically trustworthy. A model can be 90% confident and still be wrong if the data distribution changed. Calibration measures whether confidence matches actual correctness over many examples.

For Smart Cricket, this matters because the app uses uncertainty states like `uncertain` and `insufficient_quality`. Those states should eventually be tuned from real player-held-out calibration evidence, not only engineering heuristics.

## Tradeoffs

The tooling intentionally fails when player IDs are missing. It does not invent identities from filenames, because that would hide leakage risk.

The current model is not retrained in this pass. Retraining without a larger consented dataset would make the project look more complete while making the evidence weaker.

## Interview Implications

Short answer: Smart Cricket now has the tooling to evaluate generalization properly, but the actual production-quality evidence still requires a larger player-held-out dataset and coach-reviewed labels.

Deep answer: The project separates model engineering from model validity. Engineering can provide reproducible split, calibration, and report generation tools. Validity requires external evidence: more players, representative videos, coach review, and locked evaluation thresholds.
